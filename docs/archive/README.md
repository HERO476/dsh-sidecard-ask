# docs/archive —— 冻结的过程证据（不随代码维护）

这个目录（以及仓库根下同性质的两个目录）装的是**当时的证据**，不是文档正文，
也不是插件的一部分。它们的规则只有一条：**不要为了让它们"看起来还准"而改写**。

| 位置 | 是什么 | 时间锚点 |
| --- | --- | --- |
| [`../../.compat-report/`](../../.compat-report/) | 各宿主版本（桌面端 app.asar / 网页端依赖树）的兼容性探针脚本、原始 JSON 结果、页面截图 | 1.6.0 → 2.1.1 |
| [`../../design-preview/`](../../design-preview/) | 1.8.x 界面方案比选稿（SVG 方案图、原型 HTML、浅/深色与窄屏截图） | 1.8.0 前后 |

## 为什么冻结而不是删除

这些产物回答的是「**当时**为什么这样写」：某条适配是因为宿主在 alpha.4 上改了槽位目录，
某处降级是因为探针在 rc.2 上抓到了空响应。删掉它们，后来的人就只能重新踩一遍。
[`../../CHANGELOG.md`](../../CHANGELOG.md) 里每一条修复都指向这类证据。

## 为什么不维护

- 里面的 `index.js:NNN` / `client.js:NNN` 行号锚点指向**当时那版源码**。代码已经往前走了，
  这些行号不再指向同一行是**预期**，不是缺陷 —— 不要"修正"它们，那等于篡改当时的记录。
- 需要"当前代码在哪里"时，请看仍然受测试守卫的
  [`../../NODE-HOST-CONTRACT.md`](../../NODE-HOST-CONTRACT.md)：它的行号锚点由
  [`../../test/verify.mjs`](../../test/verify.mjs) 逐条校验，代码一移行测试就变红。

## 发布边界

- **npm 包不含这些目录**：`package.json` 的 `files[]` 是白名单，只有 11 个文件进包。
- **源码压缩包也不含**：`.gitattributes` 对两者设了 `export-ignore`。
- **git clone 含**：这是有意的，追溯性属于仓库，不属于发布物。
